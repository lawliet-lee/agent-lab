# 每日执行模板

把本文件复制成仓库里的 `learning-log.md`，或直接每天在末尾追加。核心只有两个动作：**开工前写一句话目标，收工前写三行记录 + git 提交**。

---

## 一、每日模板（工作日 60 分钟）

```markdown
## W07-周二 21:00–22:00 | 主题：工具结果的截断与二次摘要

今日一句话目标（可验证）：
- [ ] 让 search 工具返回超过 2000 token 时自动摘要，并打印前后成本对比

5' 回顾
- 昨天卡点：async 里混用了同步 requests，阻塞了事件循环

45' 动手（只写代码 / 只配置，不查"更优架构"）
- 做了什么：
- 结果：跑通 / 没跑通（没跑通就写清下一步第一步）

10' 落盘
- git commit：
- 三行记录：
  1. 做了：
  2. 卡在哪：
  3. 明天第一步：

超预算未完成的项 →
- ☐ 进本周末 backlog（周五统一判定：补 / 降级 / 砍）
```

三条硬性规则：

1. **目标必须能被验证**。"学一下 rerank"不合格，"跑通 rerank 并对比 top-5 质量"合格。
2. **没跑通也要提交**。把失败代码和报错一起 commit，比"今天没结果"有价值得多——W21 你会靠这些记录写失败模式分析。
3. **明天第一步写成动作**，不是"继续昨天的"。晚上 21:00 打开电脑时不该需要思考。

## 二、周六模板（120 分钟）

```markdown
## W07-周六 10:00–12:00 | 深度块

第一段 55'：项目实体工作（唯一的 55 分钟只做一件事）
- 目标：
- 产出：

休息 10'（离开屏幕，这段不能省）

第二段 55'：收口与文档
- 本周产出物是否达成：
- README / 笔记 / 演示更新：
- git commit：

最后 10'：写本周状态（只一个字）
- 完成 / 部分（缺：） / 未做
```

周日的规则只有一条：**不打开这个仓库**。休息日补课会让下周五个工作日的 1 小时同时失效，这笔账永远亏。

## 三、周自检（每第四个周六的清账日使用）

```markdown
## 阶段自检 · 第 N 周

对照阶段文件末尾验收清单：
- ☐ 达标项：
- ☐ 未达标项 → 直接写进下一阶段第一周的某个工作日任务里（不新增时间）

时间账：
- 计划 420 分钟，实际约 ___ 分钟（按 git log 提交时间粗算）
- 缺口原因：加班 / 卡住 / 走神 / 其他 ___

范围判定（三选一，不许选"下周更努力"）：
- ☐ 保持范围，接受延后里程碑
- ☐ 砍范围到 70%，保住节律
- ☐ 换更贴近现职的选题，降低准备成本
```

## 四、季度自检（W12 / W24）

只回答四个问题，每个不超过五句话：

1. 我现在能对哪类业务问题独立给出 Agent 方案，并说清成本与失败模式？
2. 我的两个项目里，哪个更能打动我的目标团队？为什么？证据是什么（试用反馈、指标数字）？
3. 过去 12 周学的东西，有多少在最近的实践里真的被用到？没用到的部分该怎么处理？
4. 下一个 12 周，我要把时间投在深度（评估/可靠性）还是广度（新框架）？理由？

## 五、常见走偏信号（出现即调整，不要硬撑）

| 信号 | 实质问题 | 调整动作 |
|---|---|---|
| 连续三天只读文档没写代码 | 1 小时的块被消费掉了，不产生能力 | 当天任务强制降级为"抄一段官方示例跑通" |
| 反复比较哪个框架更好 | 决策焦虑，逃避实现难度 | 立刻封箱：本计划只允许 LangGraph，比较留到 W20 周三 |
| 想把项目做成完整产品（加前端、加登录） | 范围膨胀 | 划到 backlog，本周只做任务表里那一行 |
| 借周六补工作日欠账 | 侵吞深度块 | 走清账周机制，周六不许用于补课 |
| 晚上 1 小时变成刷教程 | 最隐蔽的失败 | 规定每天必须以 `git commit` 结尾，没有提交就算未做 |

## 六、目录约定

主仓库 `agent-lab/` 建议保持这个结构，别中途重构：

```
agent-lab/
├── src/
│   ├── llm/           # 客户端、重试、用量统计
│   ├── prompts/       # .md 模板 + load_prompt()
│   ├── tools/         # 工具实现与 schema
│   ├── agent/         # agent_loop / context_builder / graph
│   └── retrieval/     # 索引、检索、rerank
├── mcp_servers/       # W18 起
├── evals/             # W21 起：评测集、judge、回归脚本
├── experiments/       # 对比实验结果（表格 + 原始输出）
├── projects/
│   ├── p1-assistant/  # W11 起
│   └── p2-workflow/   # W16 起
├── tests/
├── .env.example       # 只放占位，真密钥永不入库
└── learning-log.md    # 本文件内容落在这里
```

`experiments/` 是这份计划里最容易被忽略但最值钱的一目录——W23 的技术文和面试里的数字全部来自它。
