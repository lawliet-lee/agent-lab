# 阶段 4 · 多智能体、MCP 与长任务（W17–W20）

目标：完成项目二，并掌握 2026 年 Agent 工程的两块公共基础设施——协议化（MCP）与可靠性（长任务）。

## W18 · MCP（Model Context Protocol）

本周产出：一个自己写的 MCP server，把内部系统能力暴露成标准工具。

开始前花 20 分钟核对 MCP 官方规范与 SDK 的当前版本，基础设施协议变动快。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | 读官方规范概览：tools / resources / prompts 三类原语各自定位；理解它解决的是"M 个模型 × N 个工具"的集成爆炸，把 N 次私有对接变成 1 次标准实现。 | ☐ |
| 周二 | 60' | 写 MCP 客户端：接入一个现成官方 server（文件系统类），列出工具、调用、拿结果。 | ☐ |
| 周三 | 60' | 写 MCP server：选一件你真有价值的能力暴露出来（内部 API、只读 SQL、部署单查询），按 schema 定义工具与描述。工具描述质量直接决定模型会不会用对。 | ☐ |
| 周四 | 60' | 治理：鉴权、超时、错误返回约定、工具可见性（不同角色看到不同工具集）、危险操作的确认门。 | ☐ |
| 周五 | 60' | 把项目二的工具层换成 MCP server 调用，对比直连函数的方式。 | ☐ |
| 周六 | 120' | 端到端联调；写一篇"MCP 解决了什么、没解决什么"的笔记（诚实写局限：延迟、上下文膨胀、工具选择准确率）。 | ☐ |
| 周日 | — | 休息。 | ☐ |

MCP 是当前企业侧最容易被认可的能力标签之一，因为你写的 server 可以被别的团队复用——这在面试里是"有平台意识"的证据。

## W19 · 长任务与可靠性

本周产出：项目二支持中断后继续跑，且不会重复执行有副作用的操作。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | plan-and-execute：先产出结构化计划再逐步执行，支持计划修订。对比纯反应式循环在多步任务上的表现。 | ☐ |
| 周二 | 60' | 执行隔离：如果 Agent 能写代码/跑命令，把它放进受限环境（容器、资源上限、网络与文件路径白名单）。 | ☐ |
| 周三 | 60' | 重试、幂等、断点续跑。这是你的主场：把 Java 里事务边界、幂等键、补偿逻辑的思想搬过来，给每个有副作用的工具设计幂等策略。 | ☐ |
| 周四 | 60' | 异步与队列：Agent 任务放后台跑，客户端轮询或订阅进度；控制并发与队列超时。 | ☐ |
| 周五 | 60' | 人机协同：审批门（高风险动作暂停等确认）、部分执行、回滚路径。 | ☐ |
| 周六 | 120' | 项目二加固：手动 kill 进程再重启，验证能从检查点继续且不重复发通知/写数据。把结论写进 README 的"可靠性"章节。 | ☐ |
| 周日 | — | 休息。 | ☐ |
