# 阶段 0 · 地基（W01–W04）

目标：四周内拥有一件能跑的、无框架依赖的多轮对话 CLI，并让 Python 不再是后面所有事的阻力。

规则：工作日 1 小时只完成"今天这一行"。周六 2 小时做收口。周日不打开代码。

---

## W01 · Python 语法速通（面向 Java 开发者）

本周产出：仓库 `python-for-java/`，含 6 个小脚本 + 一张 Java→Python 语法对照表。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | 装 Python 3.12+、`uv`（或 venv）、编辑器 Python 插件。写 `hello.py` 跑通。理解 `.venv` 相当于项目级依赖隔离，不是 Maven 那种全局仓库概念。 | ☐ |
| 周二 | 60' | list / dict / set / tuple 与切片。把一段你用熟的 Java `Map` + Stream 过滤逻辑用推导式重写一遍。 | ☐ |
| 周三 | 60' | 函数与参数：默认值、`*args` / `**kwargs`、lambda、闭包。写 3 个纯函数小工具并互相调用。 | ☐ |
| 周四 | 60' | 类：`class` 基础、`@dataclass`（对比 Java record）、`Protocol`（对比 Java 接口，重点是"结构化子类型"这个差别）。 | ☐ |
| 周五 | 60' | 异常与资源：`try/except/else/finally`、自定义异常、`with` 上下文管理器。把一段 Java try-with-resources 翻译成 with 版本。 | ☐ |
| 周六 | 120' | 模块与包结构 + 全量类型注解 + 配好编辑器静态检查（pyright/mypy）。把本周脚本整理成一个可导入的包，写 README，完成首次 `git commit`。 | ☐ |
| 周日 | — | 休息。 | ☐ |

对照表要写成你自己踩过的坑，不要抄语法手册。例如"Java 里 `for (String s : list)` → Python 的 `for s in list`；但 Python 的循环变量在循环外还能访问，这点像 Java 的裸作用域陷阱"。

卡住怎么办：`if __name__ == "__main__"` 和 import 路径报错是本周最常见障碍，别绕开，花 15 分钟搞清模块搜索路径——后面每个项目都会遇到。

## W02 · Python 工程能力（真实调用）

本周产出：一个能跑的 httpx 客户端 + pydantic 校验 + 同步/异步性能对比脚本；注册好一个真实大模型 API。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | `requests` 与 `httpx`：请求/响应、超时设置、header。用公开测试端点（httpbin 一类）跑通 GET/POST，故意不设超时会发生什么。 | ☐ |
| 周二 | 60' | pydantic v2：`BaseModel`、字段校验、`model_validate`、嵌套模型。把昨天的 JSON 响应解析成对象——这就是你熟悉的 DTO + Jackson，但校验在边界一次完成。 | ☐ |
| 周三 | 60' | `async` / `await` / `asyncio.gather`：并发拉 10 个请求，计时对比同步版本。**这是 Java 开发者最大的门槛**，务必跑通并理解"单线程 + 事件循环"和 Java 线程池的差别。 | ☐ |
| 周四 | 60' | 密钥与配置：`python-dotenv` + `.env` + `.gitignore`。写一个 `settings.py` 统一读配置。绝对不许把 key 写进代码或提交上去。 | ☐ |
| 周五 | 60' | `pytest` 基础：测试函数命名、fixture、`@pytest.mark.parametrize`。给 W01 的工具函数补 5 个测试并全绿。 | ☐ |
| 周六 | 120' | 注册一个真实大模型 API 账号（任一主流服务商即可），跑通第一条 chat completion；把 prompt/response/usage 完整打印并记录实际花费。新建主仓库 `agent-lab/`，目录：`src/`、`notebooks? 不要`、`prompts/`、`scripts/`、`tests/`。 | ☐ |
| 周日 | — | 休息。 | ☐ |

验收：能在终端里 10 秒内用你的脚本发起一次带类型校验的 API 调用，且 `git log` 里看不到任何密钥。

## W03 · LLM API 的本质（不用任何框架）

本周产出：`llm_lab.py` —— 200 行以内、无框架的多轮对话 CLI，支持流式与 token/费用统计。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | 消息结构：system / user / assistant / tool 四类角色各自作用。做一组实验：只改 system 提示词，看输出差异，把 5 组结果存进 `experiments/`。 | ☐ |
| 周二 | 60' | 采样参数：temperature、top_p、max_tokens、stop。同一 prompt 各跑 5 次，观察稳定性与截断行为。写清"为什么同一温度两次结果不同"。 | ☐ |
| 周三 | 60' | token 与上下文窗口：写一个用量估算小工具；理解为什么长历史会爆窗口、为什么 cost = 输入 + 输出分别计价。 | ☐ |
| 周四 | 60' | 流式输出：`stream=True` 下的 chunk 结构与拼接逻辑。给对话加打字机效果，注意 tool call 在流式下是分片到达的。 | ☐ |
| 周五 | 60' | 多轮状态：messages 列表如何累积、历史裁剪的三种做法（截尾/摘要/窗口）。实现"最多保留 N 轮"的可配置策略。 | ☐ |
| 周六 | 120' | 用 `typer`/`argparse` 把上面全部拼成 `llm_lab.py` CLI，加 usage 与费用统计输出。整理并发布第一周学习笔记。 | ☐ |
| 周日 | — | 休息。 | ☐ |

本周刻意不碰 LangChain 之类的封装。理由：框架会把消息结构藏起来，而 Agent 调试 80% 的时间就是在读 messages。
