# 阶段 1 · 提示工程与工具调用（W05–W08）

目标：从"会调 API"进到"能让模型稳定地按契约输出、并驱动外部动作"。结束时你手上有一个手写的工具调用循环——这是整个 Agent 领域的心脏，先手写一遍再上框架。

---

## W05 · Prompt 与结构化输出

本周产出：`prompts/` 模板库（分类 / 抽取 / 改写三个可复用模板）+ 一个 A/B 对比脚本。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | Prompt 五要素：角色、任务、约束、示例、输出格式。重写 W03 的 system 提示词，逐条对照五要素。 | ☐ |
| 周二 | 60' | few-shot 示例选择：同一任务分别用 0/2/5 个示例各跑 10 次，记录通过率。注意示例顺序与格式一致性影响比数量更大。 | ☐ |
| 周三 | 60' | 推理类模型的边界：什么任务该让它"先想后答"，什么任务加了反而变慢变差。做 3 个任务的对照。 | ☐ |
| 周四 | 60' | 输出稳定性的工程手段：JSON schema / structured output、校验失败后的重试与自动修复策略（把校验错误回喂给模型）。 | ☐ |
| 周五 | 60' | 写一个迷你评测脚本：20 条样本 × 2 个提示词版本，统计通过率与平均 token 成本。 | ☐ |
| 周六 | 120' | 跑完 A/B 并把结果写成文档；沉淀 3 个模板为可加载的 `.md` 文件 + 变量占位，加一个 `load_prompt()` 函数。 | ☐ |
| 周日 | — | 休息。 | ☐ |

## W06 · Function / Tool Calling

本周产出：`agent_loop.py` —— 手写的模型↔工具循环，不依赖任何 Agent 框架。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | 读所选服务商官方 tool calling 文档。理解工具定义就是 JSON Schema，模型只是"生成一段符合 schema 的调用意图"，执行权在你手里。 | ☐ |
| 周二 | 60' | 单工具循环跑通：模型返回 tool_call → 你执行 → 结果以 tool 角色消息回填 → 再次请求 → 拿到最终答复。把每一步 messages 打印出来看。 | ☐ |
| 周三 | 60' | 多工具与并行调用：注册 3 个工具（如检索/计算/数据库查询），处理模型同时发起多个 tool_call 的情形。 | ☐ |
| 周四 | 60' | 错误与终止：工具抛异常时如何告知模型（错误也要作为 tool 消息返回）；最大迭代步数、单步超时、重复调用检测，避免死循环烧钱。 | ☐ |
| 周五 | 60' | 写操作的安全设计：给工具加 `requires_confirmation` 标记，实现"查询自动执行、写入需人工确认"的门。 | ☐ |
| 周六 | 120' | 把循环抽成独立模块 `agent_loop.py`：可配置最大步数/超时/日志/回调钩子。写 3 个集成测试覆盖正常、工具失败、死循环三种路径。 | ☐ |
| 周日 | — | 休息。 | ☐ |

这一步做扎实，后面所有框架都只是把它换个写法。

## W07 · 上下文工程（Context Engineering）

本周产出：`context_builder.py` —— 可插拔的上下文组装器，接到 W06 的循环上。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | 上下文预算：把窗口拆成 系统指令 / 历史 / 检索片段 / 工具结果 四块，给每块定上限并打印实际占用。 | ☐ |
| 周二 | 60' | 历史压缩：滑动窗口 + 旧对话摘要归档（摘要由模型生成，注意别让摘要污染后续判断）。 | ☐ |
| 周三 | 60' | 工具结果处理：截断策略、字段裁剪、二次摘要。实测一次"把整个数据库返回塞进上下文"和"只塞必要字段"的成本差。 | ☐ |
| 周四 | 60' | prompt caching 与成本：哪些前缀应该固定不变（系统提示、工具定义），命中率如何影响账单。跑 20 次相同前缀的请求验证。 | ☐ |
| 周五 | 60' | 指令与数据隔离：用明确分隔结构包裹用户内容与检索内容，降低被注入面。 | ☐ |
| 周六 | 120' | 实现 `context_builder.py` 并替换掉 `agent_loop.py` 里手拼 messages 的部分；跑一轮对比实验记录成本与延迟变化。 | ☐ |
| 周日 | — | 休息。 | ☐ |

### 阶段 1 验收

- ☐ 不看资料能画出手写 Agent 循环的完整时序图（含 tool 消息回填）。
- ☐ 能对"为什么这个提示词不稳"给出三种以上工程解法，而不只是"再改改措辞"。
- ☐ 有 A/B 数据证明某次提示词改动带来了质量提升且成本可控。
- ☐ 理解并实测过 prompt caching 对成本的影响。
- ☐ `agent-lab` 仓库有可复用的 `llm/`、`tools/`、`prompts/` 三层结构。
