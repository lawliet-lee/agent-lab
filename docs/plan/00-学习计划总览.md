# Java → AI 智能体开发 · 24 周在职学习计划

> 适用对象：有 Java 后端经验、Python 基本从零开始、白天上班的开发者。
> 节奏：工作日每天 1 小时，周六 2 小时，**周日强制休息**，每 4 周一个清账周。

先说一句实话，后面所有取舍都来自这句话：以 7 小时/周、共约 168 小时的投入，你不可能变成"大模型算法工程师"，但完全可以变成**能用 Agent 解决实际业务问题、并且拿得出可验证作品的 AI 应用工程师**——这恰好是当前市场缺口更大、也更能吃到你 Java 后端红利的岗位。这份计划因此把"训练/微调/数学原理"整块砍掉，把时间全部投到工具调用、上下文工程、检索、编排、评估、部署这条工程链路上。

## 一、时间模型

### 每周固定节律

| 时段 | 时长 | 用途 | 是否可挪用 |
|---|---|---|---|
| 周一～周五 21:00–22:00 | 5 × 60' | 当日主块，动手为主 | 不可挪用，这是唯一雷打不动的 1 小时 |
| 周六 10:00–12:00 | 120' | 深度块，只做项目实体工作 | 可换成周日下午，但不可拆成两个 60' |
| 周日 | — | 休息，**不许补课** | 硬性 |

每周有效投入 **420 分钟（7 小时）**，24 周约 **168 小时**。

### 通勤与午休（不占用上面的 1 小时）

这两个碎片时段只做"不需要写代码"的事：读官方文档、看昨天自己的笔记、回想某个概念怎么解释。明确禁止用来刷视频教程——那会给你"今天也学了"的错觉，但不会留下任何产出。

| 碎片时段 | 时长 | 只做这些 |
|---|---|---|
| 通勤 | 20–30' | 读当天任务对应的官方文档段落；复述昨天学的 3 个要点 |
| 午休 | 20' | 提前完成当天任务里的"阅读部分"，把晚上的 1 小时全留给写代码 |

### 每个 1 小时主块的内部分配

固定成三段，不要自由发挥：

1. **5 分钟 · 回看**：打开 `learning-log.md`，读昨天的三行记录，写下今天的第一个具体目标（一句话，必须能被验证）。
2. **45 分钟 · 动手**：只写代码或只配置环境。不查"更优雅的架构"，遇到选型分歧一律先用最笨的方案跑通。
3. **10 分钟 · 落盘**：`git commit`（哪怕只是一段草稿）+ 写三行日志（做了什么 / 卡在哪 / 明天第一步）。

关键在第三段：**每天必须留下 git 提交**。168 小时的学习，能拿出来的东西只有两种——提交记录和踩坑记录，其他都会消失。

### 周六 2 小时的用法

周六是全周唯一能做"需要连贯思路"的事的时刻：搭项目骨架、跑对比实验、写 README、部署联调。周日不要碰它，否则周一到周五的 1 小时会因为缺觉而失效。

## 二、目标与非目标

### 24 周后你手上应该有的东西（验收清单）

| # | 交付物 | 硬性标准 |
|---|---|---|
| 1 | 项目一：单 Agent 工具型应用 | 有工具调用循环、有上下文管理、部署在公网可访问、有 trace 记录 |
| 2 | 项目二：多智能体 / MCP 工作流 | 至少 1 个 supervisor + 2 个 worker，且其中 1 个工具是你自己写的 MCP server |
| 3 | 一份评测集与评测报告 | ≥30 条真实问答样本，含失败样例；改提示词后能跑回归并出分数对比 |
| 4 | 1 篇公开技术文 | 选型对比或踩坑复盘，有代码链接，不是学习笔记 |
| 5 | 简历与面试材料 | 把 Java 后端经历重写成"AI 工程底座"叙事 + 5 维度面试自评 |
| 6 | 一个可持续的 backlog | 未来 12 周继续深入的清单，避免计划结束后断掉 |

选题上强烈建议项目一/项目二都从**你现在的工作业务里**取材（日志排障助手、工单分类、SQL 生成、内部文档问答）。理由有三：你熟悉数据、有真实反馈者、成果能直接在现职被看见——转岗最容易的路径往往是内部先转。

### 明确不学（写在这里是为了让你安心跳过）

- Transformer 数学推导、注意力机制手推、损失函数细节。理解到"embedding 是向量、相似度是距离、温度是随机性"这个程度就够了。
- 预训练、全参数微调。第 22 周之后如果你还有余力，再考虑 LoRA 微调一个分类小模型。
- 框架全家桶横向对比。LangGraph / OpenAI Agents SDK / Claude Agent SDK / CrewAI 只需要在**一个**上深入，其余知道定位即可。
- 前端界面。用命令行 + 一个极简 Web 页面足够，别把时间花在这。

## 四、清账周机制（W4 / W8 / W12 / W16 / W20 / W24）

每四周有一个不学新内容的周，这是这份计划能坚持下来的核心设计，不是可选项。

规则如下：

- 周一先做**分类**：把过去三周所有未完成项标成「补」/「降级」/「砍」。
- 只补**最影响后续的一件事**。比如 W1–W3 的欠账里，`async` 不会用会卡住后面所有并发代码，而"pydantic 校验器写不熟"可以边用边学——补前者。
- 一项任务逾期最多保留 2 周，第 3 周自动降级为"读过文档、知道有这个能力"。接受覆盖不全，好过全线崩塌。
- 连续两周没完成主块 → **砍范围，不砍休息**。砍内容到 70%，也不要拿周日去填。
- 清账周周六做阶段自检：对照该阶段文件末尾的验收清单逐条打勾，未达标项直接写进下阶段第一周任务里。

## 五、你的 Java 背景在哪里是优势

不要在转岗叙事里把 Java 经历当作"要克服的过去"。Agent 工程做到后期，瓶颈从来不在提示词，而在下面这些你已经会的事情上：

| 你已经有的能力 | 在 Agent 项目里的直接价值 |
|---|---|
| 分层架构、事务、幂等设计 | 长任务的断点续跑、重试与副作用控制（W19 你会发现自己比纯算法背景的人快很多） |
| 接口契约与类型系统 | 工具 schema 设计、结构化输出校验——这是 Agent 稳定性的命门 |
| 可观测性与告警经验 | trace/span/指标体系（W21），多数 AI 应用团队恰恰缺这块 |
| 数据库与 SQL | 混合检索落地、元数据过滤、pgvector（W13–W14） |
| 线上运维与成本意识 | 模型分级路由、缓存、延迟与预算治理（W22） |

另外，Python 语法本身对你不是门槛，真正的门槛是**异步编程**和**动态类型下的工程约束**（类型注解 + pydantic）。W1–W2 会专门处理这两处。

Java 生态这条线在 W23 补一块，作为差异化：Spring AI（2.0 系列依赖 Java 21+ 与 Spring Boot 4.0）与 LangChain4j，以及阿里云的 Spring AI Alibaba（Graph 工作流方向）。不必精通，能写最小 demo 并讲清"为什么企业里某些场景用 Java 栈更合适"即可——这在内部转岗时说服力很强。

## 六、资源清单（刻意保持极少）

主原则：**以官方文档为第一来源**，第三方教程只在完全看不懂官方示例时才用。

- 模型与协议官方文档：你选定那家 API 的 tool calling / structured output / prompt caching 页面，MCP 官方规范与 SDK 文档。
- Agent 设计：Anthropic《Building effective agents》（W9 周一读，全计划最重要的一篇）。
- 编排：LangGraph 官方 tutorial（跟到能独立写条件边和 checkpointer 即可）。
- 评估与追踪：Langfuse 官方文档（自建友好）与其 Agent 评估指南。
- 中文参考：`AgentGuide`（GitHub）用于求职方向与知识图谱；六框架横评、Agent SDK 选型指南用于 W18/W23 决策参考。
- 视频：只在需要跑通第一个环境配置时看，其余一律读文档——你的 1 小时容不下视频。

所有框架与模型版本请以学习当时官方文档为准。本计划中的版本号（如 LangGraph 1.2.x、Spring AI 2.0）来自 2026 年中的公开信息，AI 基础设施更新极快，W18 与 W23 开始前各花 20 分钟核对一次。

### 预算与模型选择

工作日 1 小时的调试量很小，建议每月 API 预算控制在 50–150 元：

- 主力：一家有稳定 tool calling + structured output + prompt caching 的服务商。
- 备选：一家提供低价小模型的国内服务商，用于批量跑评测集（W21 的 30 条样本回归很吃额度）。
- 免费兜底：本地 Ollama 跑小模型，**只用于练手和数据敏感场景**，别拿它验证 Agent 复杂编排——工具调用可靠性不足会误导你的判断。
- 硬性习惯：`.env` 存密钥，进 `.gitignore`；每个项目开头就写用量统计，别等到账单出来才发现死循环。
