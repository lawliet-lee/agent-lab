# 阶段 2 · Agent 核心与项目一（W09–W12）

目标：理解 Agent 与 workflow 的分界，掌握一个编排框架的状态图模型，并在第 12 周末交付第一个能给别人试用的项目。

---

## W09 · Agent 循环原理（手写 ReAct）

本周产出：ReAct 的两种实现——文本协议版与原生 tool calling 版，附对比笔记。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | 精读 Anthropic《Building effective agents》。用自己的话写出 workflow（预定义代码路径）与 agent（模型自主决定过程与工具使用）的区别，以及为什么多数"Agent 项目"其实是 workflow。 | ☐ |
| 周二 | 60' | 手写文本协议版 ReAct：Thought / Action / Action Input / Observation 的解析循环。体会脆弱的字符串解析会带来多少 bug。 | ☐ |
| 周三 | 60' | 用原生 tool calling 重写同一个 ReAct（直接复用 W06 的 `agent_loop.py`）。对比两版在错误率、可观测性、token 成本上的差别。 | ☐ |
| 周四 | 60' | 完成判定与终止：模型说"我做完了"不可信，加显式校验节点（输出格式检查、必要字段检查、失败则再循环一轮）。 | ☐ |
| 周五 | 60' | 落盘追踪：每一步写入 JSONL（时间、消息、工具入参出参、token、耗时）。这是后面接 Langfuse 的地基。 | ☐ |
| 周六 | 120' | 加断点重放：从 JSONL 任意一步恢复继续执行。用它复现一次真实失败，并在笔记里写清你是怎么定位的。 | ☐ |
| 周日 | — | 休息。 | ☐ |

## W10 · LangGraph 状态图

本周产出：一个 3 节点图 + 把 W09 手写 Agent 迁移成图版本，附迁移对比笔记。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | 安装与核心概念：state（TypedDict/Pydantic）、node（函数）、edge（转移）、条件边。想清楚"为什么需要图而不是 if-else"——答案是可持久化、可重放、可视化、可插入人工节点。 | ☐ |
| 周二 | 60' | 实现最小图：检索 → 生成 → 校验，校验失败回到检索。跑通并打印每步状态。 | ☐ |
| 周三 | 60' | 检查点与持久化：接一个本地 checkpointer（SQLite 即可），实现同一 `thread_id` 下多轮对话状态自动恢复。 | ☐ |
| 周四 | 60' | 中断与人工介入：在写操作节点前 interrupt，恢复执行。对照 W06 周五自己手写的确认门，体会框架帮你省了什么。 | ☐ |
| 周五 | 60' | 流式输出：节点级事件流与 token 流的区别，做一个能显示"当前在哪个节点"的终端输出。 | ☐ |
| 周六 | 120' | 把 W09 的手写 Agent 完整迁移为 LangGraph 版本；写笔记：迁移中损失了什么控制、得到了什么能力。 | ☐ |
| 周日 | — | 休息。 | ☐ |

只做这一个是刻意选择——7 小时/周不足以横向比较框架。W20 的清账日你会回头补一张选型表，那时你有两个项目做参照，判断才成立。

## W11 · 项目一（上）：来自你工作的 Agent

本周产出：端到端最小闭环（能问 → 能想 → 能调工具 → 能给带来源的答案）。

选题建议（按落地难度排序，选一个你数据最容易拿到的）：日志/报错排障助手 · 工单自动分类与摘要 · 自然语言转 SQL 并执行只读查询 · 内部文档问答。

| 日 | 时长 | 今天做什么 | ☐ |
|---|---|---|---|
| 周一 | 60' | 写一页 PRD：目标用户、输入输出、3 个真实样例（含期望答案）、明确不做什么。**这 3 个样例后面就是你的评测集种子。** | ☐ |
| 周二 | 60' | 工具集设计：3–5 个工具，逐个写清入参 schema、返回字段、失败语义。数据准备：能拿到的真实样本落到本地。 | ☐ |
| 周三 | 60' | Agent 骨架：用 W10 的图结构搭出节点与状态，先让空工具跑通全链路。 | ☐ |
| 周四 | 60' | 实现 2 个核心工具 + 单元测试。剩下的工具先用假数据 stub，保证链路不断。 | ☐ |
| 周五 | 60' | 端到端打通：真实工具接上，跑通 PRD 里 3 个样例中的至少 1 个。 | ☐ |
| 周六 | 120' | 补错误处理与 JSONL 日志；录一段 30–60 秒演示；建 GitHub 仓库（README 先放截图和一句话定位）。 | ☐ |
| 周日 | — | 休息。 | ☐ |

本周铁律：**先跑通再跑好**。任何"这里应该重构"的念头都写进 backlog，不动手。

### 阶段 2 验收

- ☐ 能对"这个场景该用 workflow 还是 agent"给出有依据的判断。
- ☐ 手写循环和框架版本都实现过，能说出各自代价。
- ☐ 项目一有 PRD、有 README、有演示、有他人试用反馈。
- ☐ 每一步执行都有 JSONL 记录，且能从中定位过一次真实故障。
