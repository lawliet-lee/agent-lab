## 周一 · 五维度自评：分数不值钱，依据才值钱

**本质**：自评的唯一作用是预测"面试官第三句追问时你会不会塌"。分数只是索引，真正的产出物是每一维后面那个**文件路径**——它决定你说"我做过 RAG 评测"时，能不能在 10 秒内把东西亮出来。没有物证的自评是自我安慰。

**Java 视角**：等价于晋升述职里的能力矩阵自评。评委从不看你打的勾，只看你举的那件事有没有工单号。放到工程语言上：一个没有测试覆盖率支撑的"这块我很稳"，和没有日志的"应该没报错"是同一句话。

**核心讲解**

## 周二 · 30 分钟白板：设计一个企业级 Agent 平台

**本质**：系统设计题考的不是你能画多少个方框，是**你有没有为每个组件付过账**。多租户、工具市场、权限、评估、成本治理，每一块都存在"你只画了框、没写清失败时会怎样"的层次。今天限时 30 分钟逼出裸水平，剩下 30 分钟只做一件事：把漏掉的那三层补进同一份文件，并标出"这层我是从哪一周的哪个工件里学到的"。

**Java 视角**：这就是"给公司内部设计一个 API 网关 + 服务市场 + 发布流水线"，你的主场。新增的只有四个变量：一次调用的成本是 token 而不是连接数、输入是不可信的（自然语言里能藏指令）、行为不是确定的（同输入不同输出）、以及"上线"这个动作的判据从单元测试变成了评测集通过率。

**核心讲解**

**30 分钟的时间分配**（写在纸上，手机倒计时，到点必须换段——超时也是失败）：

- 0–4' 澄清与范围：几个租户？租户能不能自带模型和密钥？工具是否允许写操作？"上线"由谁批准？把这四个答案写在纸顶，后面所有决策引用它们。
- 4–10' 请求主路径与租户模型：入口 → 会话/权限解析 → 编排 → 工具/检索 → 生成 → 审计落库。
- 10–18' 工具市场与权限模型：注册、审核、版本、调用鉴权、确认门。
- 18–24' 评估与发布门禁：谁拥有评测集、什么分数能发、回退怎么触发。
- 24–30' 成本与容量治理：归因、预算、熔断、降级路由。

**三层最容易漏的东西**（这就是查漏阶段的对照表，逐条打勾并写一句"我漏了/我没漏"）：

1. **多租户隔离**：数据面（库、索引、向量表按租户分区）大多数人会画；漏的是**数据面之外的三条通道**——① 共享连接池与限流配额造成的噪声邻居（一个租户的批量评测把 LLM 额度吃光，另一租户的在线请求全超时）；② prompt 与 trace 里的跨租户泄漏（日志、缓存键、embedding 缓存、few-shot 示例池都必须含 `tenant_id`）；③ 检索层 ACL——这条你 W14 周五写过断言，缺字段是 fail-open 还是 fail-closed 必须说得出（默认值本身是安全设计）。
2. **工具市场的权限模型**：会画"RBAC 一张表"只是及格。要补的是：工具描述文本**是供给链的一部分**（发布者控制的描述会被用来操纵模型选择，等价于 W22 那次的注入）；工具版本漂移（发布者改 schema，上游无感）；调用前必须有**确定性校验门**，不是"提示词里叫它别越权"——W17 周四那条铁律，`enforce()` 在参数进入工具之前拦；每个工具有 owner、有最小权限声明、有写操作的确认门与幂等键（W19 周三的副作用账本）。
3. **评估与成本治理**：最容易被说成"上线后看用户反馈"。要补的是：评测集**必须有 owner**（W21 周三那条），无 owner 的评测集会随业务腐坏；发布门禁按 category 分桶设阈值，防"总体持平但拒答类崩了"；成本必须归因到 `tenant/team` 并且用 `cost_per_success` 而不是 `cost_per_run` 对外——把"贵"和"错"合并成一个决策量；预算要做熔断而不是告警（你的后端直觉在这里直接可用：没有熔断的配额等于没有配额）。

查漏阶段不许查资料，只许查你自己的三份工件：`docs/lessons/w18-governance-rules.md`（治理五条）、`experiments/w17-constraint-loss.md`（约束丢失的复现）、`evals/reports/W21-report.md` 第 7 节"已知局限"。

## 周三 · 补最弱一维 + 三个必被追问的问题（诚实纪律）

**本质**：本周唯一一次"动手"，范围锁死在周一自评里最低的那**一**维。另一半时间给三个必被追问的问题写诚实答案——追问考的不是数字大小，是**你对自己数据边界的认知深度**。数字小不致命，边界说不清才致命。

**Java 视角**：跟被问"这接口 P99 多少"一模一样。只会说一个数的人，下一句就被问死（多少流量窗口？含重试吗？P99 分母是请求数还是用户数？）。你答得出窗口与口径，反而显得可信。

**核心讲解**

三个必考题与合格答法（每条先给口径，再给数字，再给边界，最后一句"下一步我会怎么把它测准"）：

1. **"你的评测集有多大？"** → 报**原始计数 + 分桶配比 + 来源比例**，不报形容词。例："40 条，常规 16 / 边界 8 / 多跳 6 / 拒答 6 / 对抗 4；来源上真实试用回收 9 条、PRD 种子扩展 18 条、自造 13 条。对抗桶只有 4 条，所以那个桶的通过率我只当线索、不当指标。"这句话里的每一部分都能在 `evals/dataset/p1.jsonl` 和 `evals/case.py` 的配比断言里被查出来——这就是它可信的原因。
2. **"幻觉率多少？"** → **先定义再报数**。你的口径是 `groundedness ≤ 1`（引用存在但不支持论断，W21 周四的锚点），测量工具是 judge，而 judge 与人工的分层抽检同档率是 `evals/reports/W21-calibration.md` 里那个数。**样本量小的时候必须给区间不给单点**（下面的代码就是给你算这个区间的）。
3. **"多智能体为什么拆？"** → 只允许用 W17 那三个正当理由（上下文隔离 / 并行 / 权限域）之一来答，并且带上 `experiments/w17-split-decision.md` 里那条"单 Agent 具体死在哪一步"的 justification 和 `experiments/w17-multi-vs-single.md` 的实测结论。**如果那张表结论是"多 Agent 更差"，照实讲，这是你最强的答案**——它同时证明你有拆分判据和证伪能力。

**诚实纪律（本周的硬规则，不是建议）**：

- 禁止把 demo 数据当生产数据讲。没有真实流量就说"我的数据来源是 30 条脱敏历史工单，不是线上全量"。
- 禁止虚构幻觉率。没测过就说没测过，并说清"要测需要多少条样本、什么成本、多久"。
- 禁止把 judge 的绝对分对外当结论（W21 周四那条坑）；只能说"同一份 rubric 下的相对变化"。
- 禁止用"我们线上 QPS 很高 / 我们规模很大"这种无法出示证据的复数第一人称。

**把"我不知道"说成有判断力的三种句式**（背下来，今天写完，周四面试前逐条念一遍）：

- **边界式**："这个数我没测过。我测到的是 ____（已有口径），从它推 ____ 是不安全的，因为 ____。要测的话我会 ____，大约需要 ____ 条样本。"
- **归因式**："我现在没有能站住的数字，缺的是 ____（例如 negative 样本只有 5 条，阈值线的意义随索引版本会变）。我的做法是先补 ____ 再报 ____。"
- **反质疑式**："先确认要不要测这个——在 ____ 场景下这个指标不重要，因为 ____；真正该看的是 ____。"（只在真有信心时用，用错就是抢白）

**代码**

```python
"""比例类指标（通过率、幻觉率）在小样本下必须给区间，不给单点。
把它跑出来的区间宽度抄进你的答案里，就是'有边界感'的最直接证据。"""
from __future__ import annotations

import math


def wilson_95(successes: int, n: int) -> tuple[float, float]:
    """95% Wilson 区间。n=0 时返回 (0,1)：这就是'没有数据'的诚实写法。"""
    if n <= 0:
        return (0.0, 1.0)
    z = 1.959963984540054
    p = successes / n
    denom = 1.0 + z * z / n
    center = (p + z * z / (2 * n)) / denom
    half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / denom
    return (max(0.0, center - half), min(1.0, center + half))


def report(n: int, k: int) -> None:
    lo, hi = wilson_95(k, n)
    print("n=%3d 命中=%3d 点估计=%.2f  95%%区间=[%.2f, %.2f]  宽=%.2f" % (n, k, k / n, lo, hi, hi - lo))


for pair in [(34, 26), (34, 4), (8, 1), (40, 30), (120, 96)]:
    report(pair[0], pair[1])
```

跑一遍你会亲眼看到：40 条里 30 条通过，点估计 0.75，区间 [0.60, 0.86]（宽 0.26）——所以单说"通过率 75%"就是错的，说"75%，n=40，95% 区间约 0.60–0.86"才对。而对抗桶只有 4 条时区间宽到接近全量程（上面 n=8 那行是同样道理），那个桶只能当线索。

### 第一段 55'（时间账 + 四问 ①②）

**代码**（落到 `scripts/w24_time_audit.py`；跑法：`python scripts/w24_time_audit.py 2026-05-11`，参数是你计划第一周的周一）

```python
"""scripts/w24_time_audit.py —— 用 git log 算 24 周真实投入，不许靠回忆。

口径：周一到周五，某天有提交记 1 小时；周六有提交记 2 小时；周日恒为 0（不许补）。
     这是"槽位达成率"（我到场了几次），不是精确工时。可复现的粗口径比假装精确更有用。
"""
from __future__ import annotations

import subprocess
import sys
from collections import defaultdict
from datetime import date, timedelta

TOTAL_WEEKS = 24
PLANNED_H = 168.0
WEEKDAY_H = 1.0
SATURDAY_H = 2.0
PHASE_NAMES = {1: "阶段0 地基", 2: "阶段1 提示与工具", 3: "阶段2 Agent与项目一",
               4: "阶段3 检索与记忆", 5: "阶段4 编排与协议", 6: "阶段5 评估与出手"}


def commit_days() -> list[date]:
    out = subprocess.run(["git", "log", "--date=short", "--pretty=format:%ad"],
                         capture_output=True, text=True, check=True).stdout
    days: list[date] = []
    for line in out.splitlines():
        value = line.strip()
        if value:
            days.append(date.fromisoformat(value))   # 解析失败就直接抛错，别静默吞掉
    return days


def week_index(d: date, start: date) -> int:
    return (d - start).days // 7 + 1


def hours_in_week(days: list[date], start: date, w: int) -> float:
    monday = start + timedelta(days=7 * (w - 1))
    hours = 0.0
    for offset in range(7):
        day = monday + timedelta(days=offset)
        hit = sum(1 for d in days if d == day)        # 别写成 seen[day := monday] += 1：赋值目标的方括号里用海象是 SyntaxError
        if hit and offset < 5:
            hours += WEEKDAY_H
        elif hit and offset == 5:
            hours += SATURDAY_H
    return min(hours, 7.0)                            # 一周封顶 7 小时：靠周日突击不算达成


def main() -> int:
    if len(sys.argv) < 2:
        print("用法: python scripts/w24_time_audit.py <第一周周一 YYYY-MM-DD>")
        return 2
    start = date.fromisoformat(sys.argv[1])
    days = commit_days()
    if not days:
        print("仓库里没有提交记录，时间账无从算起。")
        return 1
    outside = 0
    for d in days:
        if not 1 <= week_index(d, start) <= TOTAL_WEEKS:
            outside += 1                              # 计划外加班 or 计划开始前
    phase_hours: dict[int, list[float]] = defaultdict(list)
    print("周次   槽位h   达成率   分布")
    total = 0.0
    for w in range(1, TOTAL_WEEKS + 1):
        h = hours_in_week(days, start, w)
        total += h
        phase_hours[(w - 1) // 4 + 1].append(h)
        bar = "#" * int(h) + "." * (7 - int(h))
        print("W%02d  %5.1f   %3.0f%%   %s" % (w, h, h / 7.0 * 100, bar))
    print("\n实际折算 %.1f h / 计划 %.1f h，缺口 %.1f h，达成率 %.1f%%"
          % (total, PLANNED_H, PLANNED_H - total, total / PLANNED_H * 100))
    print("窗口外提交：%d 次" % outside)
    print("\n按阶段聚合（找缺口集中在哪一段）：")
    for phase in sorted(phase_hours):
        hs = phase_hours[phase]
        worst_week = (phase - 1) * 4 + 1 + hs.index(min(hs))
        print("%-18s 均 %4.2f h/周  最低 W%02d %.1f h  零提交周 %d 个"
              % (PHASE_NAMES.get(phase, "阶段?"), sum(hs) / len(hs), worst_week,
                 min(hs), sum(1 for v in hs if v == 0.0)))
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

脚本在你本机（Python 3.9）与 3.12 下都合法：用了 `from __future__ import annotations`，所以 `list[date]`、`tuple[float, float]` 这类下标写法不会在 3.9 报错；计数一律写成显式循环或 `sum(1 for ...)`，**不要**图省事写 `counts[day := monday] += 1`——赋值目标的方括号里出现海象是 SyntaxError，任何版本都过不了。
