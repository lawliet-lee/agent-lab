## 二、补练讲义：三个最致命欠账的完整补救

挑定了 #1、#2、#3。每一节都是自足的：没欠账的跳过，欠了的今天午休或对应晚上直接照做，不需要再翻原讲义以外的任何东西。

### 补练 A · JSONL trace 与断点重放（原 W09 周五+周六）

**本质**：agent 的故障 90% 不可"重跑复现"（模型随机、数据会变），唯一取证手段是每一步的输入输出落盘，且能从任意一步恢复。

**核心机制回顾**：一行一事件，`{ts, session_id, trace_id, span_id, parent_span_id, step_idx, event, tool/input/output|model/tokens/latency, status, error}`。`trace_id/span_id/parent_span_id` 命名对齐 Langfuse（W21 接入=写个 loader，不改落盘）；`step_idx` 单调递增，是定位键也是重放切片键。写入=追加模式+每行 `flush()`。重放分两种：**纯轨迹回放**（不调模型，还原第 N 步输入，回答"当时发生了什么"）和**断点续跑**（还原状态后重新调模型往下跑，回答"从那步改会怎样"）。幂等底线：只读工具用记录输出、写操作永不自动重执行、LLM 调用重执行但输入严格还原（temperature=0 只减漂移不消漂移）。

**补救代码**（最小可用版，接进你项目一的 `tools` 节点即可）：

```python
import json
from dataclasses import dataclass, field, asdict
from datetime import datetime, timezone
from pathlib import Path

@dataclass
class Tracer:
    session_id: str
    out_dir: Path = Path("runs")
    _step: int = field(default=0)

    def log(self, event: str, *, parent: int | None = None, **payload) -> int:
        self._step += 1
        rec = {"ts": datetime.now(timezone.utc).isoformat(timespec="milliseconds"),
               "session_id": self.session_id, "trace_id": self.session_id,
               "span_id": f"{self.session_id}-{self._step:04d}",
               "parent_span_id": f"{self.session_id}-{parent:04d}" if parent is not None else None,
               "step_idx": self._step, "event": event}
        rec.update(payload)
        with (self.out_dir / f"{self.session_id}.jsonl").open("a", encoding="utf-8") as f:
            f.write(json.dumps(rec, ensure_ascii=False, default=str) + "\n")
            f.flush()          # 不 flush = 崩溃时全丢，这行的优先级等同异常处理
        return self._step

def load_events(path: Path) -> list[dict]:
    return [json.loads(l) for l in path.read_text("utf-8").splitlines() if l.strip()]

def first_error_step(events: list[dict]) -> int | None:
    e = next((e for e in events if e["status"] == "error"), None)
    return e["step_idx"] if e else None
```

**练习（30'）**：给项目一的 graph 装上 Tracer（agent_turn/tools/validate 三个点位）→ 跑 `run_eval --id S1` → 用 `first_error_step` 找一次真实失败 → 打印该步前后的事件，口头说出"输入是什么、输出是什么、为什么错"。做到即 #1 清账；trace 字段设计再深（消息快照 vs 增量）等 W21，不算欠。

### 补练 B · checkpointer 与 thread_id 会话恢复（原 W10 周三）

**本质**：checkpointer 在每个**节点边界**把 state 快照落盘，`thread_id` 是会话主键；同 thread 再 invoke，框架自动以上次终态为起点。它恢复的是"图现在是什么"，和 trace 记录的"当时发生了什么"是两套东西，都要有。

**已核实的 API 形态**：`pip install langgraph-checkpoint-sqlite`；`from langgraph.checkpoint.sqlite import SqliteSaver`；`with SqliteSaver.from_conn_string("checkpoints.sqlite") as saver:`（上下文管理器内使用）；`compile(checkpointer=saver)`；`config={"configurable": {"thread_id": "..."}}`；读快照 `app.get_state(cfg)`（`.values`/`.next`），历史 `app.get_state_history(cfg)`。官方文档新版内存版叫 `InMemorySaver`（`langgraph.checkpoint.memory`），旧资料里的 `MemorySaver` 是同物曾用名——拿到包先跑 5 行确认。

```python
with SqliteSaver.from_conn_string("checkpoints.sqlite") as saver:
    app = builder.compile(checkpointer=saver)
    cfg = {"configurable": {"thread_id": "user42-chat01"}}
    app.invoke({"messages": [HumanMessage("我叫张三，记住。")]}, cfg)
    app.invoke({"messages": [HumanMessage("我叫什么？")]}, cfg)  # 只发新消息，历史自动带上
```

**两条军规**（违反任何一条这个功能就是负收益）：接了 checkpointer 后**每轮只传增量消息**（再手动拼全历史=消息翻倍=token 暴涨+模型复读，症状出现先查这条）；`thread_id` 必须来自业务会话 ID 而非随机生成（随机=永无恢复）。`checkpoints.sqlite` 进 `.gitignore`——里面是用户对话原文，安全等级同密钥。

**练习（25'）**：双 invoke 验证记忆 → 换 thread_id 验证隔离 → `get_state_history` 找到"节点执行前"的快照 → **杀掉进程重开脚本**再 invoke，确认跨进程恢复成立。五步全过，#2 清账，周二的项目一持久化改造就是把它接进 `answer()`。

### 补练 C · 完成判定与终止校验（原 W09 周四 + W10 周二回环）

**本质**：`finish_reason != "tool_calls"` 只说明模型**停了**，不说明任务**完成**。放行必须由显式校验决定；修复要轮数上限，超限输出带 `terminated_by` 的降级结果。

**三层校验按成本排**：格式（`json.loads`/长度）→ 契约（pydantic v2：`model_validate`、`field_validator`）→ 语义（能程序判定的用程序：引用行号 ∈ 本轮工具真实行号；判不了的才 LLM judge，且 judge 也限次）。失败处理：具体错误列表回喂（"缺少字段 root_cause；引用行 L9999 不存在"），修复 ≤2 轮，然后降级。

```python
from pydantic import BaseModel, field_validator

class FinalReport(BaseModel):
    root_cause: str
    evidence_lines: list[int]
    next_action: str

    @field_validator("evidence_lines")
    @classmethod
    def non_empty(cls, v: list[int]) -> list[int]:
        if not v:
            raise ValueError("证据行不能为空")
        return v

def validate_final(raw: str, known_lines: set[int]) -> tuple[FinalReport | None, list[str]]:
    try:
        rep = FinalReport.model_validate_json(raw)
    except Exception as e:
        return None, [f"输出不符合契约: {e}"]
    fake = [n for n in rep.evidence_lines if n not in known_lines]
    if fake:
        return None, [f"引用了不存在的日志行 {fake}，只允许引用工具返回中的行号"]
    return rep, []
```

图版接法：`validate` 节点把结果写 `state["errors"]`，条件边 `errors 非空且 repairs<2 → agent_turn（回喂错误）`，否则 END；`recursion_limit` 是第二层熔断（数节点执行次数，不是你的轮数——语义要自己换算）。降级输出字段枚举沿用 W09：`model_done_validated / repair_exhausted / max_steps / budget`。

**练习（20'）**：把 `validate_final` 接进项目一 validate 节点，用两个坏输出（缺字段/引用编造行）验证都被拦下并正确回喂 → `run_eval` 的 PASS 判定改为以校验器结果为准，肉眼判定作废。#3 清账。

## 五、范围判定指引：保范围 / 砍到 70% / 换选题

连续两周周五状态出现"未做"或同一个"缺什么"，触发本节判定。三种处置不是态度问题，是有明确判据的技术决策：

**保范围（继续按 W13-W16 原计划走）**，同时满足三条：
1. 欠的是**体验型**任务（文本协议版、流式 UI 这类），不是**地基型**（trace/checkpointer/校验器）；
2. 项目一端到端已通至少 1 条样例——链路存在，只是不精致；
3. 拖延原因是时间事件（加班/生病），不是系统性判据失效。
执行：砍掉的项标"降级：读过文档、知道有这个能力"，写进 backlog，**不再内疚**。

**砍到 70%（保选题，砍功能）**，出现任一信号：
1. 项目一"能问能答"还没通，而你已经花了两晚在格式/性能上；
2. 补练清单里"地基型"欠账 ≥2 项；
3. 你的工具集有 5 个但只真实化 1 个。
砍法（按对阶段 3 的损害从低到高排，先砍前两项）：演示界面/CLI 美化 → 第 3 个以后的真实工具（留 stub，链路照跑）→ 多跳样例（S3 级）改单跳 → 流式输出。**绝不砍的三项**：trace 落盘、最大步数/成本熔断、危险操作确认——这三项对应"安全与成本"硬习惯，砍了等于阶段 3 带着裸奔的项目走。"砍内容到 70%，也不要拿周日去填"是 00 文件第四节的原条款，执行优先级高于你的自尊。

**换选题**，同时满足才换：
1. **数据前提塌了**——选题依赖的数据你拿不到（要审批/脱敏成本超过两周工时/样本里根本没有样例期望的证据行）；W11 周二数据准备那天就该发现，现在发现也算发现；
2. **反馈前提塌了**——找不到一个愿意第二次试用的真实用户；没有反馈者的项目到 W21 也长不成评测集（样本从哪来？）；
3. 已投入 ≥2 周且不是"刚写完 PRD 就腻了"（区分方法：把当前卡点写成一句话，如果卡点是"无聊/枯燥"是后者，如果卡点是"这个输入永远拿不到返回"是前者）。
换法：**只换场景不换资产**——PRD 结构、tools 契约、graph 骨架、tracer 全部复用（这就是上周工程方法的意义），选题降级到四选一里数据最容易的（多数人是"工单分类"：单跳、有现成标签、无危险操作）。换选题在周六自检里记为"部分+已换题"，不算失败——**转岗作品集里"止损判断"同样是能力项，面试讲这个故事比讲顺利更可信**。

最后一句给周五的试用环节：这一步价值极高且常常推翻你的 PRD——如果它真的推翻了，恭喜，阶段 2 最值的两小时花完了。
