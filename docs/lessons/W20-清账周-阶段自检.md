## 二、补练讲义：三个最致命欠账的完整补救

下面三段是本周的主菜。它们都接你已有的模块，命名不同就只改 import——**别在这里重新造一套项目二**。

### 补救 1 · 分派错误的失败注入（周二）

W17 周二写的 `enforce()` 是确定性校验器，它判"worker 返回的领域是否匹配分派"。你多半只在正常路径上见过它返回 True。测试的写法是**把 worker 换成一个必然给错领域的假实现**，而不是去求模型出错。

```python
# tests/test_p2_failures.py
from __future__ import annotations

import pytest

from src.agent.supervisor import enforce   # W17 周二的确定性校验器
from src.agent.state import TaskAssignment, WorkerResult   # 名字以你 W17 的实现为准


class WrongDomainWorker:
    """必然把日志域的问题答成配置域——模拟分派错到不可信的那一类。"""

    async def run(self, task: TaskAssignment) -> WorkerResult:
        return WorkerResult(
            assignment_id=task.id,
            domain="infra-config",           # 与 task.expected_domain 故意不一致
            text="把连接池上限改成 50 就行了。",
            evidence=[],                       # 也没有引用，两道判据一起触发
        )


@pytest.mark.asyncio
async def test_misassigned_worker_is_rejected_not_trusted() -> None:
    task = TaskAssignment(id="t-1", query="昨晚订单服务超时是因为连接池吗", expected_domain="logs")
    verdict = enforce(task, await WrongDomainWorker().run(task))
    assert verdict.ok is False
    # 硬要求：拒绝理由必须是可回喂的文本，不是 "校验失败" 四个字。
    # 模型只有读到"领域不匹配，该任务要求 logs"才知道下一步该怎么改。
    assert "logs" in verdict.reason
```

三个判据，逐条对上 W17 立过的规矩：`enforce` 是**确定性**的（不许在里面调模型）；拒绝理由必须写清"怎么改对"；被拒的 worker 结果**不许进最终答案**。

补一条断言值得单独试一次：把 `enforce` 换成一个永远返回 ok 的假实现，确认你的 supervisor 会真的把错领域的答案交给用户。**如果你的测试在有 `enforce` 和没有 `enforce` 时结果一样，那这条测试什么都没测**——这是给自己的测试做体检最快的办法。

### 补救 2 · 重复副作用实验（周二，难度最高）

阶段 4 验收里最容易被蒙过去的一条是"可中断续跑**且不重复副作用**"。"能续跑"很好演，"不重复"必须有证据。做法是**用同一个 `thread_id` 把中断段跑两次**，断言账本里只有一条、下游只被调一次。

```python
# tests/test_p2_resume.py
from __future__ import annotations

import pytest

from src.runtime.effects import Ledger, stable_key   # W19 周四：账本 + 稳定键生成
from src.runtime.jobs import run_job_with_ledger     # W19：跑一步并把副作用登记到 Ledger


class FakeGateway:
    """把有副作用的那一步换成计数器：真实扣款/发工单在测试里绝不该发生两次。"""

    def __init__(self) -> None:
        self.calls: list[str] = []

    async def __call__(self, payload: dict) -> str:
        self.calls.append(str(payload["idempotency_key"]))
        return "ok"


@pytest.mark.asyncio
async def test_resume_twice_charges_once(tmp_path) -> None:
    ledger = Ledger(str(tmp_path / "ledger.sqlite"))
    gw = FakeGateway()

    async def run(attempt: int) -> None:
        # 同一 thread_id、同一步、跑两次——第 attempt 次里 resume 走的路径完全一样
        await run_job_with_ledger(thread_id="job-42", step="charge", ledger=ledger, gateway=gw)

    await run(1)
    await run(2)
    assert len(gw.calls) == 1, f"副作用被执行了 {len(gw.calls)} 次，幂等键没生效"
    assert len(set(gw.calls)) == 1
    # 关键：幂等键必须来自(任务, 步骤)而不是时间戳或随机 uuid——否则重放必然生成新键，账本形同虚设
    assert gw.calls[0] == stable_key("job-42", "charge")
```

这段代码里最容易写错的是**幂等键的生成**。用 `uuid4()` 或 `time.time()` 做键，第一次跑必然成功、第二次也必然再执行一次，因为键变了。键必须是从业务里推出来的稳定值：`f"{thread_id}:{step}:{effect_hash}"`。你在 W19 如果已经用了随机键，今天就是补这个 bug——**这个 bug 在演示里永远看不出来，只在事故里看得出来**。

### 补救 3 · MCP server 不可用时的显式降级（周二收尾）

W18 周五留了一句"今天先把失败处理写成显式的 `BridgeConnectError`（W20 周二会补成测试）"。今天兑现。

```python
# tests/test_p2_bridge_down.py
from __future__ import annotations

import pytest

from mcp import Client, MCPError      # W18 周二装上的 SDK v2
from src.agent.supervisor import Supervisor   # W17 的 supervisor，名字以你的实现为准


class BridgeConnectError(RuntimeError):
    """你自己的异常类型——编排层只认它，不认 SDK 的原始异常。"""


def connect_bridge(params):
    """连接失败必须抛你自己的类型，而不是把 SDK 的原始异常漏给编排层。"""

    async def _open():
        try:
            client = Client(params)
            await client.__aenter__()
        except (OSError, MCPError) as exc:   # 进程起不来 / 协商失败都归到这里
            raise BridgeConnectError(str(params)) from exc
        return client

    return _open()


@pytest.mark.asyncio
async def test_dead_server_degrades_instead_of_crashing_the_run() -> None:
    boss = Supervisor(bridge=None)           # 强制走"没有外部工具"那条降级路径
    result = await boss.answer("订单服务昨晚为什么超时")
    assert result.ok is True                 # 降级不是失败：整条链必须还能给人一个结果
    assert result.tools_used == []
    # 硬要求：降级必须在答案里显式声明，不能假装是"模型自己想出来的"
    assert "诊断工具不可用" in result.caveats
```

三条判据说清"什么叫处理好了"：**不崩**（外层还能返回结果）、**不装**（答案里带 caveat 说明少了哪条证据）、**不静默**（日志与 trace 里有一条明确的重试/放弃记录）。只满足第一条叫掩盖问题。

**周三 60'**：框架选型表。三个维度：定位、控制粒度、生态位。表格骨架：

| 维度 | LangGraph | OpenAI Agents SDK / Responses | Claude Agent SDK |

**写法要求（这比填什么更重要）**：

- **别写版本号**。版本三个月就换，写死了这张表当月就过期。要写"这一类需求它给不给一等公民支持"。
- **每一格后面必须挂一个你自己的事实**。比如"控制粒度"这格，你要说得出"我的回环出口是校验器决定的还是模型决定的"（W10 立过这个判据），或者"我图里 `interrupt()` 之后状态落在哪"。挂不出事实的那一格留空，别猜。
- 这三家都在往同一个方向收敛（无状态协议、MCP 做工具层），差异主要落在**抽象层放多少在你手里**。MCP 这一侧的已核实事实可以直接用：规范 2026-07-28 移除了 `initialize` 握手、协议级会话与 `ping`，Roots / Sampling / Logging 转为废弃而非删除，Python SDK v2 里 `FastMCP` 已改名 `MCPServer`。具体 API 形态**当场核对各自官方文档**，写不清就标注"（此处以官方文档为准）"——这不是偷懒，这是这张表能不能活过三个月的关键。
- 最后一行是重点：**这张表的价值是让你能回答"你为什么用 LangGraph 而不是 X"**，W24 周一的自评和面试都会直接引用它。它不是给别人推荐工具用的。

## 五、范围判定指引：三条路怎么选

- **保范围**：五项里最多 1 项"没做"，且它不是验收表第 1、2 条。
- **砍到 70%**：连续两周没达标（查 `learning-log.md` 的周状态行）。砍的时候按这个顺序砍：**架构图 → 选型表的"生态位"维度 → 补救 3 → 周五预读**。绝不砍补救 2（重复副作用）和周二测试日——那两条是阶段 4 的全部实质。
- **换选题**：如果项目二做到这里你发现自己根本讲不清"它比项目一多了什么"，那不是执行力问题，是选题问题。回到 W16 的选题判据重挑一次，这比硬撑一个自己都不信的项目省时间。

欠账最多保留 2 周。第 3 周它自动变成"砍"，写进砍掉清单，**不许再提**。

## 本周术语卡

| 术语 | 一句话解释 | 为什么重要 |
|---|---|---|
| 失败注入 | 把依赖换成必然出错的假实现，验证你的闸门真的会拦 | 只测 happy path 的测试等于没有 |
| 测试体检 | 故意把被测逻辑改坏，看测试会不会红 | 不会红的测试是装饰品 |
| 幂等键 | 从(任务, 步骤)推出的稳定标识，重放时不变 | 随机键会让账本形同虚设 |
| 降级 | 组件不可用时仍返回结果，并显式声明少了什么证据 | 不崩 / 不装 / 不静默，三条缺一不可 |
| `BridgeConnectError` | MCP 连接失败的自有异常类型 | 把 SDK 原始异常漏给编排层，等于没人能诊断 |
| 框架选型表 | 用"这一类需求给不给一等公民支持"为单位的判断表 | 版本会变，判据不会 |
| 一张图一个问题 | 架构图的取舍原则 | 画全的图讲不了 3 分钟 |
| 清账 / 降级 / 砍 | 欠账的三种合法出口 | 没有"以后再补"这个选项 |
