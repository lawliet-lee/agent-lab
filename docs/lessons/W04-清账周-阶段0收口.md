## 补练讲义（只挑最致命的三项，独立可读）

### 补练 1 · 异步：三句话建立正确直觉

**规则**：协程函数必须被 `await`；同步阻塞函数在协程里等于卡住整个进程；并发上限必须显式设。

自检实验（5 分钟，跑完就懂）：

```python
import asyncio
import time


async def task(name: str, seconds: float) -> str:
    await asyncio.sleep(seconds)  # 让出控制权：等待期间其他任务能跑
    return name


async def bad_task(name: str, seconds: float) -> str:
    time.sleep(seconds)  # 阻塞：整个事件循环停在这里，其他任务全部等待
    return name


async def measure(fn, label: str) -> None:
    start = time.perf_counter()
    async with asyncio.TaskGroup() as tg:
        for i in range(5):
            tg.create_task(fn(f"t{i}", 1.0))
    print(f"{label}: {time.perf_counter() - start:.2f}s（并发 5 × 1 秒）")


async def main() -> None:
    await measure(task, "正确 await")        # ≈ 1.0s
    await measure(bad_task, "同步阻塞混入")   # ≈ 5.0s —— 并发完全失效


asyncio.run(main())
```

看懂这 1 秒 vs 5 秒，你就掌握了异步的全部要点。**真实场景里 `bad_task` 伪装得非常好**——它是一个看起来无害的 `requests.get()` 或 `client.chat.completions.create()`（同步 SDK）。所以规矩是：**只要进了异步路径，链路上一律异步 API**。

三个高频修正动作：

1. 只有同步库可用 → `await asyncio.to_thread(legacy_fn, arg)`。
2. 并发数失控 → `asyncio.Semaphore(n)` 包住请求函数体。
3. 想"发完就不管" → 用 `TaskGroup`，不要用裸 `create_task`（会孤儿）。

**自测**：`asyncio.run(asyncio.sleep(1))` 为什么合法但没用？`await asyncio.gather(a(), b())` 与 `a(); b()` 差在哪？

### 补练 2 · pydantic v2：把校验错误变成可行动信息

地基阶段的坑是"能解析成功就行"，但 W05 之后你要**拿校验失败去驱动模型重试**，所以要会读、会转述错误。

```python
from pydantic import BaseModel, Field, ValidationError


class Filter(BaseModel):
    field: str
    op: str = Field(pattern=r"^(eq|ne|gt|lt|in)$")
    value: str | int | float | list[str] | None = None
    limit: int = Field(default=50, ge=1, le=500)


def validate_model_output(raw: dict) -> tuple[Filter | None, str]:
    """返回 (对象, 可回喂给模型的修复指令)。这是 W05 自动修复的最小原型。"""
    try:
        return Filter.model_validate(raw), ""
    except ValidationError as exc:
        lines = [f"- { '.'.join(str(p) for p in e['loc']) or '<root>' }: {e['msg']}" for e in exc.errors()]
        fix = "你的输出不符合约定结构，请按以下错误修正后只重新输出 JSON：\n" + "\n".join(lines)
        return None, fix


bad = {"field": "status", "op": "equal", "value": "paid", "limit": 5000}
f, fix = validate_model_output(bad)
print(f)      # None
print(fix)
# - op: String should match pattern '^(eq|ne|gt|lt|in)$'
# - limit: Input should be less than or equal to 500
```

三个要点：`e["loc"]` 给出**字段路径**（嵌套时形如 `("filters", 0, "op")`）；`e["msg"]` 是人类可读描述；把两者拼成回喂文本比"请重新输出"有效得多——模型知道自己错在哪才会真改。

**自测**：为什么 `extra="forbid"` 对你自定义的请求体是好事？`model_dump(exclude_none=True)` 什么时候必须用？

### 补练 3 · 让 messages 可读：Agent 调试的第一技能

W03 让你把请求体打印出来。这一步做扎实，后面你会省下大量时间。养成一个固定工具函数：

```python
import json
from typing import Any


def dump_messages(messages: list[dict[str, Any]], *, title: str = "request") -> None:
    """调试用：完整结构 + 长度摘要。注意内容里可能有敏感数据，日志级别控制。"""
    print(f"\n----- {title}：{len(messages)} 条 -----")
    for i, m in enumerate(messages):
        content = m.get("content")
        preview = (content[:120] + "…") if isinstance(content, str) and len(content) > 120 else content
        print(f"[{i}] role={m['role']}")
        if m.get("tool_calls"):
            for tc in m["tool_calls"]:
                print(f"      tool_call id={tc.get('id')} name={tc['function']['name']} args={tc['function']['arguments']}")
        if m.get("tool_call_id"):
            print(f"      回应 tool_call_id={m['tool_call_id']}")
        if preview is not None:
            print(f"      content={preview!r}")
    print(f"     合计字符 {sum(len(str(m)) for m in messages)}")
    print(json.dumps(messages[-1], ensure_ascii=False)[:300], "…\n")
```

**规矩**：任何 Agent 相关代码，出问题时**第一步是打印 messages，第二步才是怀疑模型**。W09 会把它接进 JSONL 落盘，W21 升级成 trace。今天先练到熟练。
