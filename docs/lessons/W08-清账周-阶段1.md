### 补练一 · 回填链与循环收敛（对应诊断点 1 + 2）

**自检**：① 一个 `assistant` 消息带了 3 个 `tool_calls`，你回填了几条 `tool` 消息？顺序有要求吗？② 模型连续 5 步用完全相同的参数调同一个工具，你的循环在哪一步停？靠什么判定"相同"？③ 请求体里的 messages 缺了 `tool_call_id`，报错来自服务商还是来自你的代码？

**机制**：服务商侧的对话是无状态的——每轮把全部消息重发一遍。tool calling 只是把这规则加严了一层：**模型发起的每一次调用都必须有一条对应的 `role="tool"` 消息闭环**，因为下一轮的采样会读这些结果。三条推论：
- `tool` 消息只能跟在"带 `tool_calls` 的 assistant"之后，且必须用 `tool_call_id` 精确配对；`content` 必须是字符串（对象要先 `json.dumps`）。
- N 个并行调用就要 N 条回填。少一条 → 服务商 400；多一条 → 结构对不上，同样 400 或行为诡异。
- 模型自己那一步的 `tool_calls` **必须原样 append 回 messages**（包括 `id`）。不回填，等于你替模型把话说了一半，它下一轮会重新发明一个调用。

收敛性则是另一件事：模型不会主动保护你。它可能反复用同一个错误参数调同一个工具，因为每次回填的错误信息都长得差不多。护栏必须在你的代码里，四条：最大步数（max steps）、单步超时（step timeout）、重复调用检测（duplicate detection）、token 预算。每条都要留下显式 `stop_reason`，否则事后无法区分"正常结束"和"被闸拦下"。

**代码**：一个自己就能跑的结构性自检，接在每次发请求之前。有它，400 会变成你自己抛的错，且带行号。
```python
class LoopShapeError(RuntimeError):
    pass
def check_backfill(msgs: list[dict]) -> None:          # 发请求前调用：违规当场抛错，别等服务商 400
    pending: dict[str, str] = {}                       # tool_call_id -> 工具名
    for i, m in enumerate(msgs):
        role = m.get("role")
        if role == "assistant" and m.get("tool_calls"):
            pending = {c["id"]: c["function"]["name"] for c in m["tool_calls"]}
            continue
        if role == "tool":
            if not pending: raise LoopShapeError(f"第 {i} 条 tool 消息前面没有 assistant(tool_calls)")
            cid = m.get("tool_call_id")
            if cid not in pending: raise LoopShapeError(f"第 {i} 条 tool_call_id={cid} 不在待回填集合里")
            if not isinstance(m.get("content"), str): raise LoopShapeError(f"第 {i} 条 tool.content 不是字符串")
            pending.pop(cid)                           # 配对成功
        elif pending and role != "assistant":
            raise LoopShapeError(f"第 {i} 条 {role} 插在未闭合的回填链中间")
    if pending: raise LoopShapeError(f"{len(pending)} 个 tool_call 没有回填结果")
```

### 补练二 · 结构化契约与修复回喂（对应诊断点 3）

**自检**：① `json_object` 模式和 `json_schema` + `strict` 差在哪一层保证？② strict 模式对 required 和 `additionalProperties` 有什么硬性要求？③ 模型返回 `"category": "网络"`（中文）而你的枚举是 `["infra","network",...]`，`ValidationError` 之后你做的第二件事是什么？

**机制**：`json_object` 只约束"合法 JSON"，字段名、枚举值、层级全靠模型自觉。`json_schema` + `strict` 是**采样时屏蔽不合法 token**——它保证的是结构合法（字段齐、类型对、不多不少），不保证语义正确（值可能是编的）。所以两件事必须分开：结构错由 schema 拦，语义错由 pydantic 校验器 + 回喂（repair retry）处理。strict 模式的常见约束（各家略有差异，以你所用服务商文档为准）：所有字段必须 required、对象必须 `additionalProperties: false`、不支持 `minimum`/`pattern` 这类格式约束、嵌套层数与属性总数有上限、和 `parallel_tool_calls` 互斥。

**代码**：把 pydantic 生成的 schema 改成 strict 可接受的形式，再做带错误回喂的请求。**注意 `content` 可能是 `None`**，这是最常见的第一个崩点。
```python
import json
from typing import Any, Awaitable, Callable, TypeVar
from pydantic import BaseModel, ValidationError
T = TypeVar("T", bound=BaseModel)
class SchemaRepairFailed(RuntimeError):
    pass                                                       # 调用方据此区分"结构病"和"业务病"
def to_strict(schema: dict) -> dict:                   # 全字段 required；可选用 ["x","null"] 表达
    def walk(node):
        if isinstance(node, list): return [walk(x) for x in node]
        if not isinstance(node, dict): return node
        node.pop("title", None); node.pop("default", None)
        if props := node.get("properties"):
            node["additionalProperties"] = False
            node["required"] = list(props)
        return {k: walk(v) for k, v in node.items()}
    return walk(schema)
async def ask_structured(model: type[T], msgs: list[dict], *,
                         chat: Callable[[dict], Awaitable[Any]], attempts: int = 2) -> T:
    body = {"model": MODEL_NAME, "temperature": 0, "messages": msgs,
            "response_format": {"type": "json_schema", "json_schema": {
                "name": model.__name__, "strict": True, "schema": to_strict(model.model_json_schema())}}}
    for _ in range(attempts + 1):                      # 上限 2 次修复：再多就是把预算花在赌运气上
        raw = ((await chat(body)).choices[0].message.content) or ""     # None 兜底，否则 validate 直接崩
        try:
            return model.model_validate_json(raw)                       # pydantic v2 写法
        except ValidationError as e:
            errs = json.dumps(e.errors(include_url=False, include_input=False), ensure_ascii=False)
            msgs += [{"role": "assistant", "content": raw},              # 模型说过的话要留在上下文里
                     {"role": "user", "content": f"上次输出不符合 schema，按错误逐项修正后只输出 JSON：{errs}"}]
    raise SchemaRepairFailed(model.__name__)           # 到此为止：修不好就抛错，别偷偷降级成 dict
```

- [ ] 造 5 条必失败的输入（缺字段、多余字段、枚举中文、数字写成字符串、外面裹了一层代码围栏），确认 `ask_structured()` 在前 2 次内修好的比例，并记录哪个最难修。
- [ ] 故意把 `strict` 关掉跑同样 5 条，对比通过率与 `prompt_tokens`——这是"结构保证值不值得"的一手数据。

**达标判据**：`experiments/` 里有这张对比表：修复次数 × 通过率 × 平均输入 token，并能一句话说明为什么修复次数要设上限。

### 补练三 · 用数据证明成本可控（对应诊断点 4）

**自检**：① 你现在这个循环，一轮请求大概多少 `prompt_tokens`？② 一次 10 轮的演示任务总共花多少钱（人民币，保留两位）？③ 缓存命中占了多少 token，命中率从第几轮开始上升？答不出任何一个就是欠账。

**机制**：成本 = 输入 token × 轮次 × 单价。轮次由循环护栏决定，输入由 W07 的四块预算决定，单价由你选的模型决定——**三个变量全都可测**，所以"贵"从来不是模型的问题，是没做预算和没命中缓存。缓存那边再强调一次因果：只有**逐字节相同的前缀**才复用计算，命中部分按折扣计价，写入按原价（折扣与 TTL 各家不同，字段名以你所用服务商文档为准）。要证明成本可控，就要有一份能重算的账本，而不是一张截图。

**代码**：把三周的账本压成一句能对外说的话。
```python
# scripts/cost_report.py
import json, pathlib, statistics
PRICE = {"in_per_1k": 0.012, "out_per_1k": 0.036}      # 元/千 token，从价格页抄，并在旁边写更新日期与 URL
READ_DISCOUNT = 0.10                                            # 命中部分的计价系数，查不到就标"未确认"，别默认 1 折
def load(path: str = "logs/context_usage.jsonl") -> list[dict]:
    p = pathlib.Path(path)
    if not p.exists(): raise SystemExit("账本不存在：先去 W07 周一把 record() 接进循环")
    return [json.loads(x) for x in p.read_text(encoding="utf-8").splitlines() if x.strip()]
def main() -> None:
    r = load()
    prompt = sum(x["prompt_tokens"] for x in r)
    cached = sum(x.get("cached_tokens", 0) for x in r)             # 字段名各家不同：先确认再算，别当 0 混过去
    out = sum(x["completion_tokens"] for x in r)
    saved = cached * (1 - READ_DISCOUNT) / 1000 * PRICE["in_per_1k"]   # 命中部分按折扣计价，省下的就是这段
    cost = prompt / 1000 * PRICE["in_per_1k"] + out / 1000 * PRICE["out_per_1k"] - saved
    print(f"请求 {len(r)} 次 | 输入 {prompt} | 命中 {cached} | 输出 {out}")
    print(f"花费 {cost:.2f} 元 | 单请求输入 P50 {statistics.median([x['prompt_tokens'] for x in r]):.0f}")
    print(f"最贵一轮 {max(x['prompt_tokens'] for x in r)} tokens，超预算 {sum(x['over_budget'] for x in r)} 次")
if __name__ == "__main__":
    main()
```

**达标判据**：一条命令产出报告，且你能指着其中一个数说"这个数字上周是 X，因为做了 Y 才变成现在这样"。

## 三、阶段 1 验收：逐条给出"怎么验证自己达标"

**⑤ 仓库有可复用的 `llm/`、`tools/`、`prompts/` 三层结构**
操作：跑 `find src -name "*.py" | sort`，肉眼确认 `llm/`、`prompts/`、`tools/`、`agent/`、`context/` 各有内容且被真正 import 过（没被引用的模块不算分层，算垃圾）。再验证依赖方向单一：`prompts` 不 import `tools`，`tools` 不 import `agent`，只有 `agent` 可以聚合上层。
不达标信号：`agent_loop.py` 里还硬编码着 system 文本或工具 JSON；或者 `prompts/` 里的模板写着工具的返回字段名（层次泄漏）。

### 周三 · 给 `agent_loop.py` 加"单步重放"调试命令
**为什么要它**：Agent 出问题时，"看最终答案"毫无价值，有用的是"第 4 步到底发了什么、模型回了什么"。没有这个命令，你后面每次调试都在 `print` 里临时加代码，加完还删不干净。
```python
# src/agent/replay.py：把每一步的请求与响应原样落盘，之后可按步回看
import json, pathlib, time
LOG_DIR = pathlib.Path("logs/steps")
def dump(step: int, request: dict, response: object) -> None:
    LOG_DIR.mkdir(parents=True, exist_ok=True)
    row = {"step": step, "ts": time.time(), "request": request,
           "response": response if isinstance(response, dict) else str(response)}
    (LOG_DIR / f"step-{step:02d}.json").write_text(json.dumps(row, ensure_ascii=False, indent=2), encoding="utf-8")
def show(step: int) -> None:                            # python -m src.agent.replay show 4
    row = json.loads((LOG_DIR / f"step-{step:02d}.json").read_text(encoding="utf-8"))
    msgs = row["request"].get("messages", [])
    print(f"步骤 {row['step']} | {row['request'].get('model')} | 上下文 {len(msgs)} 条")
    for i, m in enumerate(msgs):
        names = [c["function"]["name"] for c in m.get("tool_calls", [])]
        print(f"  [{i}] {m.get('role','?'):<9} {str(m.get('content') or '')[:70]}" + (f" → 调用 {names}" if names else ""))
    print("响应：", json.dumps(row["response"], ensure_ascii=False)[:400])
```
- [ ] 在循环的 `on_step` 钩子里调 `dump()`，跑一次 5 步任务，确认 `logs/steps/` 每步一个文件。
- [ ] 实现 `show(step)` 子命令与 `last`；再补一个"从第 N 步重放"：读第 N 步的 messages，用假 LLM 或真模型重发一次，观察是否复现同一步行为（不能复现就说明有隐藏随机源，比如没固定 temperature）。
- [ ] **硬性**：把 `logs/` 加进 `.gitignore` 并验证 `git status` 干净。重放文件里有完整上下文，包含真实工单数据和可能的凭据——密钥与生产数据不入仓库，这条没有例外，也不做"脱敏后再提交"的妥协。
- 产出物：`replay.py` + 任意一步的可读快照。

### 周四 · 写踩坑记录：模型不遵守 schema 的真实表现
写作要求：只写你**真的撞过**的，每条给三行——现象（贴原始 `content` 或报错）、根因（机制层面，不是"模型不行"）、工程处置（代码位置）。至少覆盖下面这些类别里你撞过的部分，没撞过的去制造一次：
1. **包一层壳**：返回 `{"result": {...}}` 而不是裸对象。根因：训练分布里 JSON 常挂在某个键下。处置：strict schema 让多余键不可能。
2. **代码块围栏**：```` ```json ... ``` ````。处置：`response_format` 或本地剥围栏，剥完仍要 `model_validate_json`。
3. **`content` 为 `None`**：常见于带 `tool_calls` 的那一步被误当作文本响应读。处置：`(content or "")`，先判 `tool_calls` 是否存在。
4. **枚举同义替换**：`network` 写成 `网络`/`net`/`Network`。根因：语义正确但字面不同，`json_object` 模式管不住。处置：strict + 回喂，或把枚举值写进字段 `description` 再测一轮。
5. **可选字段用 `null`、空串、还是缺省不写**：三种都合法但语义不同。根因：strict 要求全字段 required，"可选"只能靠 `["string","null"]` 表达。处置：DTO 里显式 `| None`，别指望模型理解"没写就是没有"。
6. **数字写成字符串**：`"confidence": "0.8"`。根因：中文运维文本里的数字带单位，模型走保守路径。处置：pydantic `field_validator` 做类型窄化，或 strict 下重试。

## 五、范围判定指引：三条路怎么选

清账周结束时要做一个明确选择。三者都合法，**最错的是什么都不选继续硬扛**。

| 选择 | 判断依据（同时满足 ≥2 条才选它） | 具体做法 | 后果与代价 |
|---|---|---|---|
| **A 保范围** | 本周主线那 1 项补达标了；45' 动手完成率 ≥4/5 天；API 预算没爆（仍在 50–150 元/月内） | 原计划进 W09；把降级项写进对应周的前置任务 | 进度最快，但要求你不再新增欠账；连续两周同一项"缺什么"复现就自动失去资格 |
| **B 砍到 70%** | 连续两周没完成主块；阶段 1 验收 ≥2 条无证据；工作上有突发加班把节律打散 | 保留主干（`agent_loop.py`、`context_builder.py`、一次 A/B、一份成本报告），把"3 个模板""四组对照实验""评测脚本"降级为读到过；W09 起始不变 | 作品少但能力链完整。**休息一天都不许砍**——砍周日换来的是第三周全崩，这是机制原文的硬约束 |
| **C 换更贴近现职的选题** | 当前选题（运维工单）在公司里完全用不上，导致每次动手都在编数据；或你已明确知道内部要落地的场景是别的 | 保留全部代码结构，只换数据源与工具集：换成你现在天天碰的系统（内部工单、发布流水线、日志查询、SQL 只读视图）。代码不动，`tools/` 与样本换掉 | 上手成本几乎为零，动机和素材立刻变真；代价是要重跑 A/B 与成本基线（约一个周六） |

选择提示：
- 判断"该 B 还是该 C"只看一个问题——**你缺的是时间还是燃料**。缺时间选 B，缺燃料（没兴趣、数据靠编）选 C；两者都缺先选 C，因为换选题几乎不花时间。
- 换选题不要换阶段目标。阶段 1 要的是"手写循环 + 契约 + 成本证据"，任何数据源都能给出这三样。
- 三条路都要在 `learning-log.md` 写下**一句为什么**，W20 清账周会回来看这句话。

## 本周术语卡

| 术语 | 一句话解释 | 为什么重要 |
|---|---|---|
| backfill / 回填 | 把工具执行结果以 `role="tool"` + `tool_call_id` 塞回 messages | 少一条就 400，Agent 最常见的结构性错误 |
| loop guard / 循环护栏 | 最大步数、单步超时、重复调用检测、token 预算 | 模型不会保护你的钱包，只有代码会 |
| stop reason / 终止原因 | 循环结束时显式记录的结束类型 | 区分"正常答完"和"被闸拦下"的唯一依据 |
| repair retry / 修复回喂 | 把校验错误结构化地反馈给模型重试 | 语义错靠它；次数必须设上限 |
| structured output / 结构化输出 | 采样期屏蔽非法 token，保证 JSON 合 schema | 只保证结构，不保证事实 |
| cost ledger / 成本账本 | 每轮 `usage` 落盘的 jsonl 文件 | 没有账本，所有成本结论都是形容词 |
| replay / 单步重放 | 按步取出当时的请求与响应重新观察 | Agent 调试唯一有效的抓手 |
| scope judgement / 范围判定 | 保范围 / 砍到 70% / 换选题的明确三选一 | 不判定就是全线崩塌的开始 |
