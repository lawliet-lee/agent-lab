### 补练 A · 20 条标注集 + recall/hit-rate/MRR（原 W14 周一）

**本质**：检索质量必须是可计算的。做法是人工事先声明"这个问题该命中库里的哪几个 chunk"，再看检索把它们排到第几。这一步没做，你后面所有优化都是在拟合噪声。

**三个指标的定义（用哪套就要说得清）**：

- `recall@k = 命中的应相关文档数 / 应相关文档总数`（与排名无关）。
- `hit-rate@k`：二值版本，top-k 至少命中一条记 1，再对查询求平均。RAG 端到端更贴近体感——生成端只需要证据在场。
- `MRR@k = (1/N) Σ 1/rank_i`，`rank_i` 是第 i 题**第一条**相关结果的名次（从 1 起），未命中记 0 且计入平均。严格 MRR 要算全排序，我们只有 top-k，所以报 MRR@5 并写明。rerank 的收益主要落在这里。

**标注格式**（JSONL，一行一查询）：

```jsonc
{"qid": "q01", "question": "导出的数据文件多久会被删掉", "relevant_ids": ["a3f1...9c"],
 "kind": "positive", "why_hard": "口语化提问，文档写的是'保留期'", "expected_answer": "7 天"}
```

分层：8 直白事实题 + 5 词面/语义错配题 + 4 词面精确题（单号、错误码、代码符号、数字）+ 3 跨文档/多段题；另外补 5 条 `kind: "negative"`（供补练 C 的阈值）。`relevant_ids` **必须**用 SQL 从库里取，不许手写：

```bash
psql "$PG_DSN" -c "SELECT chunk_id FROM chunks WHERE content LIKE '%保留 7 天%' LIMIT 5;"
```

**代码**：`metrics.py` 全文见 W14 周一讲义，此处给最小可跑版（欠账者今晚抄这一份就够，别去翻旧文件）：

```python
"""metrics_min.py — 三个指标 + 逐题明细。"""
from __future__ import annotations

import json
from pathlib import Path
from pydantic import BaseModel, Field


class Label(BaseModel):
    qid: str
    question: str
    relevant_ids: list[str] = Field(min_length=1)
    kind: str = "positive"


def positives(path: Path = Path("evals/labels.jsonl")) -> list[Label]:
    rows = [Label.model_validate(json.loads(l)) for l in path.read_text("utf-8").splitlines() if l.strip()]
    return [r for r in rows if r.kind == "positive"]      # 负样本没 relevant_ids，混进来会把 recall 算成 0


def recall_at_k(rel: set[str], got: list[str], k: int) -> float:
    return len(rel & set(got[:k])) / len(rel)


def hit_rate_at_k(rel: set[str], got: list[str], k: int) -> float:
    return 1.0 if rel & set(got[:k]) else 0.0


def rr_at_k(rel: set[str], got: list[str], k: int) -> float:
    for i, cid in enumerate(got[:k], 1):
        if cid in rel:
            return 1.0 / i
    return 0.0


def evaluate(labels: list[Label], ranked: dict[str, list[str]], k: int = 5) -> dict[str, float]:
    missing = [l.qid for l in labels if l.qid not in ranked]
    if missing:
        raise ValueError(f"结果缺 qid {missing}：切分参数变过，或 id 不是从库里取的")
    n = len(labels)
    f = lambda fn: round(sum(fn(set(l.relevant_ids), ranked[l.qid], k) for l in labels) / n, 4)  # noqa: E731
    return {"n": float(n), "recall@5": f(recall_at_k), "hit-rate@5": f(hit_rate_at_k), "MRR@5": f(rr_at_k)}
```

**练习（40'）**：写 12 条起步（今天先够跑通，明后天补到 20 条）→ 用 W13 的 `search.py` 逻辑批量检索出 `ranked` → `evaluate` 出三个数字并写进 `experiments/w16_rag_report.md` 第一行 → **自检公式**：构造"每条只命中第一个 relevant 且排在 rank 1"的假结果，此时若某题有 3 个 relevant，`recall@5` 应约 0.33、`hit-rate@5` 与 `MRR@5` 应为 1.0；三个数全相等说明 `recall` 被误写成了二值命中。

### 补练 B · 三方案对比表（原 W14 周二/三/六）

**本质**：一条命令、一份索引、一份标注集，只换检索路径，产出 recall/MRR/延迟/成本四列。这张表是 W23 技术文的核心图表和简历上唯一的数字资产。

**核心机制回顾（够你独立实现，不必回看讲义）**：

- **BM25**：`from rank_bm25 import BM25Okapi`；语料与查询必须用同一个中文分词器（`jieba.lcut`，没有 jieba 就退化成字符 bigram）；`BM25Okapi(tokenized_corpus).get_scores(tokenize(query))` 返回与语料同序的分数数组；**分数为 0 的必须截断**（无共同 token 时它仍会返回一堆 0 分文档污染融合）。
- **RRF**：`score(d) = Σ 1/(k + rank)`，`k=60`，`rank` 从 1 起。只用排名不用分值 → **不需要归一化**两路分数（BM25 无上界、余弦 0~1，硬加权每换一次模型就得重标定）。`k=60` 的作用是抹平头部差距：rank1 与 rank2 只差约 1.6%。
- **两阶段 rerank**：粗召回 top-50 → 精排 top-5。双塔（查询与文档独立编码，文档不知道谁在问）分不清否定词与数值差异；交叉编码器把 `query + doc` 拼一起逐对打分，精度高但不能预计算，所以只喂小候选池。接口固定成 `rerank(query, docs, top_n) -> list[(doc, score)]`，实现可换（云端 `/rerank` 或本地 `CrossEncoder`）。
- **为什么必须固定其他变量**：recall 的方差来源有切分参数、embedding 模型、索引参数、top_k、粗召回池大小、标注集。中途动任何一个，差异无法归因，表格作废。今天开始前先全量重建一次索引并冻结参数。

**脚本骨架**：

```python
"""run_compare_min.py — 每条路径返回 (top-5 chunk_id, 秒)，指标复用补练 A。"""
from __future__ import annotations

import os, statistics, time
from collections import defaultdict
from typing import Callable

from metrics_min import evaluate, positives


def rrf(rank_lists: list[list[str]], k: int = 60) -> list[str]:
    acc: dict[str, float] = defaultdict(float)
    for ranks in rank_lists:
        for rank, cid in enumerate(ranks, 1):          # rank 从 1：写成 0 会让首位贡献变成 1/k
            acc[cid] += 1.0 / (k + rank)
    return [c for c, _ in sorted(acc.items(), key=lambda x: -x[1])]


def run(paths: dict[str, Callable[[str], tuple[list[str], float]]], repeat: int = 3) -> list[dict]:
    labels = positives()
    ranked: dict[str, dict[str, list[str]]] = {name: {} for name in paths}
    lat: dict[str, list[float]] = {name: [] for name in paths}
    for name, fn in paths.items():
        for l in labels:                                # 先 warm-up 再计数，否则首条含连接建立与模型加载
            ids, sec = fn(l.question)
            ranked[name][l.qid] = ids
            lat[name].append(sec)
        for _ in range(repeat - 1):
            for l in labels:
                lat[name].append(fn(l.question)[1])
    return [{"path": name, **evaluate(labels, ranked[name]),
             "p50_ms": round(statistics.median(lat[name]) * 1000, 1),
             "p95_ms": round(sorted(lat[name])[int(len(lat[name]) * 0.95) - 1] * 1000, 1)}
            for name in paths]
```

**练习（55'，占下周六第一段的一半也行）**：把 A/C/D 三条路径实现到 `paths` 字典里 → 跑 `--repeat 3` → 填表 → 补一列单次成本（embedding token × 单价 + 生成 prompt/completion token × 单价 + rerank 文档 token × 单价；不确定单价就记调用次数，别写"几乎免费"）→ 表下写三句话结论：最优路径与理由、线上你选哪条以及为什么可能不是指标最好的那条、哪个改动性价比最低被砍。**额外一行**："每提升 0.01 recall 要多花多少毫秒/多少钱"——面试里这句最亮。

### 补练 C · 引用 + 拒答闸门 + 一条越权断言（原 W15 周一/二 + W14 周五）

**本质**：RAG 的结构缺陷是 ANN 永远返回最近的 k 个，哪怕都很远——所以库里没有答案时模型会尽力编。拒答机制 = 分数不过线时**根本不进生成**。引用机制 = 只允许模型引用本轮给它的编号，编造可自动检出。这两件事是"敢给别人用"与"demo"的分界线。

**阈值标定四步**：① 取 20 条 positive 的 top-1 分数；② 造 5 条 negative，其中至少 2 条"近似但无解"型（库里只有"导出上限 5 万行"，就问"3 万行时怎么申请特批"——这种最能骗过模型也最能测出阈值）；③ 排序看正例下界与负例上界之间的空隙（经验区间：正例 cosine 常在 0.55~0.85，负例 0.30~0.50，中间是灰区）；④ 取空隙中点偏保守处，把 `metric`、理由、索引指纹写进配置。**注意余弦不是校准过的概率**：换 embedding、改切分、语料翻倍之后同一条线的含义就变了，必须随索引版本重标定。分数尺度也不许混用（BM25 分数无上界，rerank logits 可为负）。

```python
"""refuse.py — 闸门 + 引用真实性，两条硬判据。"""
from __future__ import annotations

import re
from dataclasses import dataclass

CITE = re.compile(r"\[(\d{1,2})\]")


@dataclass(slots=True)
class Gate:
    metric: str = "cosine"          # cosine / rrf / rerank_score：尺度不同，禁止跨用
    min_top1: float = 0.55          # 你自己的标定值，别留默认值上线
    index_fingerprint: str = ""

    def allow(self, hits: list[tuple[str, float]]) -> tuple[bool, str]:
        if not hits:
            return False, "no_result"
        return (True, "ok") if hits[0][1] >= self.min_top1 else (False, "below_threshold")


def check_citations(text: str, valid_idx: set[int]) -> tuple[list[int], list[int]]:
    cited = list(dict.fromkeys(int(m) for m in CITE.findall(text)))     # 顺序去重；允许 [1][3] 多引用
    return cited, [i for i in cited if i not in valid_idx]              # 第二个非空 = 编造，拒绝该输出
```

**越权断言（20 分钟，阶段验收第 3 条的物证）**：

```python
import os, psycopg
from acl import Principal, search_acl            # 检索层过滤见 W14 周五；BM25 那一路必须同样过滤

dsn = os.environ["PG_DSN"]
with psycopg.connect(dsn) as conn:
    alice = {r[0] for r in conn.execute("SELECT chunk_id FROM chunks WHERE metadata->>'owner'='alice'")}
hits = search_acl(Principal("bob", max_sec=1), qvec, public_docs=[], k=10)
assert not (alice & {c for c, _ in hits}), "检索层泄漏：别人的 chunk 进了候选"
```

顺带记住那行密级条件的写法差异：`coalesce((metadata->>'sec_level')::int, 0) <= %(s)s` 是 **fail-open**（漏打标 = 按最低密放行）；`((metadata->>'sec_level')::int) <= %(s)s` 让缺失变 NULL，被 `WHERE` 滤掉，是 **fail-closed**。默认值本身是安全设计。

验证动作：现场走 W15 周六那六步演示（reindex 幂等 → 有引用 → 会拒答 → 换 user_id 事实不同 → 杀进程续聊 → 越权 0 条），录屏存进 `demo/`。`git log --oneline` 里有 `p1-v2` tag；README 至少含检索子系统图、W14 对比表、"如何核查一条回答"、"拒答策略与阈值标定方法"、已知问题 ≥5 条且**含一条真实未做项**（例如 `inferred` 记忆无人工复核队列）。全绿的 README 不算过——那说明你没写真实状态。

**⑤ 项目二 PRD 已写完。**
验证动作：出示 `projects/p2-workflow/PRD.md`，六节齐（问题定义/用户与场景/输入输出契约/编排拓扑/失败与降级/不做清单），且拓扑图里能指出 supervisor、2 个 worker、以及 W18 那个自建 MCP server 挂在哪个位置。缺"不做清单"就退回周三重写——清账周之后你的最大风险是范围失控，不是能力不足。

五条过三条以上判"完成"；只过两条写"部分（写明缺什么）"，并把缺项直接写成 W17 周一的任务。**别为了全勾把"部分"改成"完成"，这张表的读者只有你自己。**

## 五、项目二选题指引（三个候选方向）

选题判据沿用 00 文件第二节：从你现在的工作业务里取材——你熟悉数据、有真实反馈者、成果能在现职被看见。三个候选方向各自的难度：

| 方向 | 取材难度 | 数据可得性 | 面试价值 | 主要风险 | W17/W18 契合度 |
|---|---|---|---|---|---|
| A. 内部需求 → 技术方案初稿（需求文档进，多 agent 产出方案草稿 + 风险清单 + 接口草案） | 中低：写作类任务，无需真实系统接入 | 高：需求文档你手里就有，脱敏成本低 | 高：直接展示"结构化产出 + 多 agent 分工 + 引用"，且产出物可给人看 | 容易做成"一个大 prompt 的长输出"，多 agent 变成装饰；评审会追问"哪里真的需要 supervisor" | 契合：worker = 检索员（历史方案/规范）、设计员、审稿员；MCP server 自然落在"读取需求单系统" |
| B. 代码变更影响分析（一次 MR/commit 进，产出受影响服务、接口、测试与灰度建议） | 高：要真解析 diff/调用图，且你的仓库权限要申 | 中：diff 好拿，但调用关系与依赖表常拿不全 | 最高：**有确定性事实做锚点**（影响面可以被证伪），最能体现工程深度，也是 Java 背景差异化最强处 | 数据前提最容易塌——若拿不到依赖/调用关系数据，最后只能做成"读 diff 讲故事"，价值掉一半 | 契合：worker = 静态分析员、知识库检索员、风险评估员；MCP server 落在"代码/仓库查询"，W18 最自然 |
| C. 值班告警分诊与处置建议（告警进，分诊定级 + 相似历史告警 + 处置步骤 + 是否需升级） | 低：告警文本是结构化又短，样本量大 | 高：告警历史与工单一般能导出，脱敏相对容易 | 中高：闭环价值好讲（降噪、缩短 MTTR），且天然含"权限边界"（只读 vs 可执行处置动作） | 历史告警的"正确处置"标签往往没人记，评测集 expected 难定；容易和已完成的项目一（日志排障）撞场景，被问"这两个有什么区别" | 契合：worker = 分诊员、检索员（历史告警/预案）、处置建议员；MCP server 落在"告警平台只读接口" |

**给三条明确建议**：

1. **优先 A 或 C，B 只在你确认"能拿到调用关系数据"时选**。判据一句话：W11 周二那天你学会的数据验证法——今天就去要 5 份真实输入样本，拿不到就换题，别赌"下周应该能要到"。B 的天花板最高，但它是最容易在 W19 卡死数据的那一个。
2. **与项目一必须有明显的场景差异**。项目一是"日志排障"（单 agent + 只读工具 + 时序证据）。选 C 就要在 PRD 里写清差异（多租户告警路由 + 处置动作的确认边界 + 相似案例检索），否则面试官会认为你只做了一个东西的两遍。A 天然不撞，这是它被推荐的主要原因。
3. **选题要留一个"必须多 agent 才成立"的环节**。判据：该环节的产出会被下一个 agent 消费、且中间需要独立审核（例如设计员出方案 → 审稿员按规范 checklist 打回 → 设计员修订）。如果整条链路能塞进一个 prompt，W17 你就会被迫造出无意义的分工——这种项目在评审里一眼就看得出是为了用框架而用框架。

顺带把阶段 4 的伏笔埋进 PRD 的"不做清单"：明确写"本周不做前端、不做真实写操作、MCP server 只做只读接口"。清账之后的最大敌人是范围，不是难度。
